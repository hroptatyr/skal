Description

Overview

skal is a lightweight ontology for modelling transitive alignments (if A aligns to B, and B aligns to C, then A also aligns to C) without asserting statements on the aligned concepts themselves. It models alignments as reified individuals that group two or more concepts, and optionally qualify their validity in time and/or their distance to each other.

Using reification, skal allows for assertions to exist where they belong: as third‑party, auditable claims. Altering (or more precisely contaminating) concepts is not necessary.

Inspired by SKOS's only transitive property to assert matches, skos:exactMatch, a special class skal:ExactMatch is introduced: It represents an alignment with indefinite temporal validity and a diameter of 0.

Motivation

External vocabularies, third‑party thesauri, legacy datasets, or community standards are most likely not under one's control. And yet, resources of different publishers or data vendors sometimes need to be aligned because parts of a system or workflow reference one resource whereas other parts might use concepts from a second resource.

Perhaps the prominent example is the financial industry with its competing symbologies, classifications, or rating systems. Unlike open data or open access collections (think Wikidata, geonames, RefSeq, UniProt, etc.) vendors in the financial industry regularly refuse to acknowledge a competitor's scheme as part of the vendor lock-in strategy. But even in open data or open access systems the evolution of concepts may affect the "exactness" of alignment information over time.

What's needed is alignment as a first‑class entity, owned, named, and governed by the aligning party. And what must be avoided are large, redundant cliques of pairwise skos:exactMatch triples.

An example

In 1974, the majority of ISO 3166 codes was released. As a preparation the committee carefully assembled a list of sovereign states and dependent territories. The findings went into what the country level code (ISO 3166-1) entails, a backing definition if you will. The 1974 definition of of the ISO 3166-1 alpha-2 code DE reads: the Federal Republic of Germany.

Similarly, but unfortunately not contemporarily, Wikidata introduced the concept of the Federal Republic of Germany (Q713750). It is thinkable, if not likely, that an editor in 1974 were to equate these two:

 wd:Q713750 skos:exactMatch iso3166-1-adj:DE .

After the unification of FRG and GDR in 1990 ISO went on to add a remark: "the code elements for the former German Democratic Republic (DD, DDR, 278) have been incorporated into the code elements for Germany." But essentially the scope of ISO code DE was left untouched.

Meanwhile, Wikidata added a replacement concept, Q183, to accomodate for unified Germany, and updated the alignment to:

wd:Q183 skos:exactMatch iso3166-1-adj:DE .

and invalidated the alignment in Q713750. This is problematic. Q183's history begins in 1990 whereas DE's history begins in 1949, efficaciously, or 1990 and 1974, respectively, in terms of validity. It could be argued that exactMatch is the wrong qualifier on account of different temporal scopes.

Even if RDF* (or reification) is used to capture:

<<wd:Q713750 skos:exactMatch iso3166-1-adj:DE>>
        tempo:validFrom "1974"^^xsd:gYear ;
        tempo:validTill "1990"^^xsd:gYear .
<<wd:Q183 skos:exactMatch iso3166-1-adj:DE>>
        tempo:validFrom "1990"^^xsd:gYear .

the semantics of SKOS don't allow for both ground assertions to live in the same graph. A reasoner would unforgivingly infer:

wd:Q713750 skos:exactMatch wd:Q183 .

because of transitivity.

Strictly adhering to SKOS the solution would be to demote both assertions to skos:closeMatch on account of different temporal scopes between all concepts in question which in hindsight, and without incorporating version history, leaves us guessing if there had ever been an exact match.

skal to the rescue

As mentioned before, skal is aware of concepts that diverge in time. The example would simply be modelled as:

[]
        a skal:ExactAlignment ;
        skal:aligns wd:Q183 , iso3166-1-adj:DE ;
        tempo:validFrom "1990"^^xsd:gYear ;
        dct:replaces [
                a skal:ExactAlignment ;
                skal:aligns wd:Q713750 , iso3166-1-adj:DE ;
                tempo:validFrom "1974"^^xsd:gYear ;
                tempo:validTill "1990"^^xsd:gYear .
        ] .

(in this case using blank nodes, and with Dublin Core terminology to link replacements)

A reified n-ary alignment describing a SKOS exactMatch group.

This is a convenience class to allow for migrating existing skos:exactMatch collections to skal.
Note

Individuals of this type employ the same semantics as skos:exactMatch assertions. That is, a second individual that aligns one of the concepts of the first individual is considered owl:sameAs this first individual. And thereby capturing the transitive closure of all concepts on the subject and object side of a skos:exactMatch collection.

metric c

IRI http://purl.org/skal/Metric
Description

The metric used to express the diameter of an alignment.
Note

It is (currently) beyond the scope of skal to define named individuals of this type with rigour. There are four well-known kinds of n-ary metrics:

  1. n-metric: Given a metric d between two concepts (i.e. d(x,x) = 0, d(x,y) = d(y,x), and d(x,y) <= d(x,z)+d(z,y)) an n-metric can be defined as D(x_1,...,x_n) := Σ_{i<j} d(x_i,x_j), the following properties hold as per the underlying metric's axioms: D(x,...,x) = 0, D(x_1,...,x_n) = D(x_σ(1),...,x_σ(n)), D(x_1,...,x_n) <= d(x_1,z) + D(z,x_2,...,x_n), and monotonicity: D(x_1,...,x_k,x_k,...) <= D(x_1,...,x_k,x_(k+1),x_(k+1),...).

  2. n-ultrametric: Given an ultrametric u between two concepts (i.e. u(x,x) = 0, u(x,y) = u(y,x), and u(x,y) <= max{u(x,z),u(z,y)}) an n-ultrametric can be defined as U(x_1,...,x_n) := max_{i<j} u(x_i,x_j), the following properties hold as per the underlying ultrametric's axioms: U(x,...,x) = 0, U(x_1,...,x_n) = U(x_σ(1),...,x_σ(n)), U(x_1,...,x_n) <= max{u(x_1,z), U(z,x_2,...,x_n), and monotonicity: U(x_1,...,x_k,x_k,...) <= U(x_1,...,x_k,x_(k+1),x_(k+1),...).

  3. MST length: Given a metric d between two concepts, the MST length is defined as MST(X):=min_T Σ_(i,j)\in E(T) d(x_i,x_j), where E(T) is the set of edges of the spanning tree T. The following properties hold: MST({x,...,x}) = 0, MST({x_1,...,x_n})=MST({x_σ(1),...,x_σ(n)}), MST(X∪Y)<=MST(X∪Z)+MST(Z∪Y), and monotonicity: MST({x_1,...,x_k,x_k,...}) <= MST({x_1,...,x_k,x_(k+1),x_(k+1),...}).

  4. Steiner tree length: Given a metric d between two concepts, the Steiner tree length is defined as ST(X):=inf_T Σ_(u,v)\in E(T) d(u,v) where E(T) is the set of edges of a tree whose vertex set contains X and any number of Steiner points. The following properties hold: ST({x,...,x}) = 0, ST({x_1,...,x_n})=ST({x_σ(1),...,x_σ(n)}), ST(X∪Y)<=ST(X∪Z)+ST(Z∪Y), and monotonicity: ST(x_1,...,x_k,x_k,...) <= ST(x_1,...,x_k,x_(k+1),x_(k+1),...).

The first two of which can be traced to the metric distance of individual pairs of points (aka concepts) whereas the latter two are global in nature. ST even employs points (i.e. concepts) that aren't part of the original set of concepts in its definition.

Between these four the following holds over a fixed underlying (binary) metric d: ST <= MST <= U <= D.

metric op

IRI http://purl.org/skal/metric
Description

Metric used for the diameter value of the alignment.

Because alignments are inherently n-ary the term metric is to be understood in a more general fashion, e.g. n-metric, or n-ultrametric, MST path length, or Steiner tree length, etc.

Moreover, the lower bound of any metric is 0, which holds iff all concepts are exactly aligned. That means an alignment with diameter 0 need not explicitly state the metric used, and if it does the metric must be considered interchangeable with any other metric.
Domain alignment c
Range metric c
